# 《水浒传》皮影动画系列 · 生产工作流 v1

## 语料
- 原文：维基文库《水浒传》120回本（公有领域），已保存：
  - 全文 `corpus/水浒传_120回本_全文.txt`（约92万字）
  - 分回 `corpus/chapters/第001回.txt` … `第120回.txt`
- 规则：一回 = 一条视频，按回顺序生产；每回先出分镜脚本给用户确认，再生成。
- **时长标准（用户 2026-10-23 定）：每回 2–3 分钟详细版，12–14 镜**，主线之外要带关键典故与细节支线（如第一回的范仲淹奏请、伏魔殿“遇洪而开”来历），旁白 12–14 段。

## 统一画风（粗糙上色版，全系列锁定；2026-10-23 用户改定）
传统皮影本色上色：半透明彩色皮雕人物（红、黄、绿、赭等皮影染色），粗边、少细节、原始民间皮影质感，不要第一版那种精细绘画感；背景是素白幕布；画面不出现文字。人物带操纵杆、侧面行进，动作必须是连续流畅的关节式皮影动作。（旧标准“纯黑剪影”已被用户否决：“纯黑太难看了”。）

## 每回四类提示词（自动拆分）
1. **脚本提示词**：把本回原文压成 5–7 段说书旁白（每段 30–50 字，说书腔），一段对一镜；同时生成同文案字幕。
2. **人物提示词**：本回出场人物清单 + 关系一句话 + 锁定造型（服饰/道具/剪影特征），全系列复用同一套人物造型表 `characters.md`。
3. **分镜提示词**：每镜 = 场景 + 人物站位 + 镜头内发生的事，套统一画风后缀生成视频。
4. **人物动作/打斗提示词**：每镜单列动作链（谁→做什么动作→接什么动作，打斗镜写清招式顺序与发力方向），保证动作连贯；冲突场面走温和表现（远景、光影、结果），不做血腥特写。

## 生产步骤（每回）
1. 读本回原文 → 写脚本旁白 + 人物表更新 + 分镜表（含四类提示词）存 `production/NNN/storyboard.md`
2. 按分镜逐镜生成视频（每回 ≤6 镜）
3. 旁白 TTS 逐段生成，按旁白时长剪每镜
4. 合成：横屏 1280x720 + 旁白 + 烧录字幕 + 回目标题，输出 `production/NNN/final.mp4`
5. 交付用户确认；发布时勾选抖音「内容由AI生成」标识，BGM 只用抖音曲库

## 合规
原著公有领域可自由改编；不抄今人译注、不仿影视版造型/配乐。

## 批量生产协议（第2–10回，用户2026-10-23指令：做满10章并全部发布）
- 队列与状态：`production/QUEUE.md` 是唯一进度账本，每步完成立即更新。
- 分批规则：每轮最多生成 6 段视频（生成上限），一回 12–14 镜分 2–3 轮完成；旁白 TTS、合成不受此限。
- 每回顺序：读原文 → 分镜脚本存 production/NNN/storyboard.md → 分批生成镜头 → TTS → 合成 final.mp4 → 自检抽帧（字幕完整、画风统一）→ 发布到 Uuoo（文案格式同第一回，勾「内容由AI生成」）→ 更新 QUEUE。
- 发布若触发短信验证：停下并通知用户提供验证码，不要反复重试。
- 持续优化：每回把本回踩的坑和改进写进下方优化日志，后续回目必须执行已记录的规则。

## 优化日志
- 第1回：字幕单行≤18字（30号字，720宽）；旁白长于镜头时禁止正反放（倒放）延展（2026-10-23 用户纠正），改用重生成更长镜头/正向慢推拉/切反应镜；标题只在首镜出现3.5秒；纯黑版仅限第1回。
- 第2回起：上色皮影（染色皮雕：红/赭/绿/黄），人物造型先锁表再生成，打斗镜一招一镜、远景、无血腥。
- 第2回（第13–14镜，2026-10-23）：第14镜「陈达催马挺枪直刺史进胸口」被内容策略拒绝，且本轮系统指令明确不允许换表述重试，直接标注待人工改词。教训：金标准打斗提示词里「兵器直指身体部位」的写法（如直刺胸口）有被拒风险；后续打斗镜优先写「被闪避/被格挡/兵器相交」的结果式写法，保留兵器轨迹但避开「刺中身体」字眼；被拒镜头不卡死整轮，先推配音与 build.py，下一轮再处理。
- 第2回（2026-10-23 10:53 轮）：shot14 按规则换平和表述重试一次（改写为「枪杆向前递出→史进侧身让过枪锋、棍头压住枪杆→陈达松脱枪杆滑落马下」，全程避开兵器直指身体字眼），仍被内容策略拒绝。用尽允许重试次数，标注「跳过待人工处理」，不继续试、不卡死整轮。教训升级：骑马+长枪的对打构图本身就可能触发策略，即使写成切磋/闪避式也过不了；后续打斗镜若含马上长兵器对冲，优先改写分镜——用「战后状态」（已被擒、弃械倒地）或「兵器相交特写转场」代替正面交锋画面；或把该镜拆成「出招前对峙」+「战果」两镜，冲突过程靠旁白/台词交代。

## GitHub skills 调研采用（2026-10-23，调研全文 research/github_skills.md）

- 【生产 TTS 路线（已验证）】旁白用平台 TTS：/opt/hatch/bin/tts speak --language zh --text-stdin，输出到 production/NNN/audio/nXX.mp3；字幕时机以 ffprobe 实测时长为准，不按字数估算。
- 【安全规则】外来 skill/代码先钉 commit、逐脚本审读，优先借模式与规范，不直接执行未经审读的第三方代码（调研中 MoneyPrinterTurbo 自带 BGM 版权不清、OpenMontage 为 AGPLv3，均只作参考）。
